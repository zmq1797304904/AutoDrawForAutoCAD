# AutoDrawForAutoCAD — 坐标照片批量识别并自动绘制到 DWG

针对工程测量场景的效率工具：将全站仪/RTK 手簿屏幕拍成照片后，脚本自动 **OCR 识别照片中的坐标**，并**在 AutoCAD 图纸上按坐标绘制红色圆 + 绿色高程文字标注**，替代人工逐点照屏输入。

## 功能流程

```
集成主窗 → 选择图片来源（文件夹 / Word文档）→ 选择 DWG → 调整绘图参数（可选）→ 点击开始 → OCR + AutoCAD 绘图全自动
```

1. 启动后弹出**集成主窗**：上半部分为文件选择栏（图片来源 + 目标 DWG + 浏览按钮），中部为绘图参数面板，下半部分为运行日志区（实时显示 OCR 识别结果与绘图进度，关键信息按 emoji 着色：✅成功/❌失败/⚠️警告/📝备注/🔧应用备注）
2. 支持两种图片来源，可同时使用：
   - **图片文件夹**：直接扫描 png/jpg/jpeg/bmp
   - **Word 文档 (.docx)**：自动提取文档内嵌图片（按段落顺序），并解析每张图上方文字备注（详见下文"备注规则"）
3. 每张照片识别出 **东坐标 / 北坐标 / 高程** 三项（截断到小数点后 3 位，毫米精度），实时打印在日志区供核对
4. 识别成功的每组坐标绘制两个实体（识别失败的照片自动跳过，不会画错点）：
   - **红色圆**：半径 0.5m，图层为 **长崖边巷道**（图层不存在时自动创建）
   - **高程文字**：三位小数高程值（如 `343.495`），绿色、文字高度 0.8、宽度因子 0.8、样式 Standard，居中叠加在圆的正中央，图层为 **长崖边巷道高程文字标注**（自动创建）
5. 绘制完成后视图自动缩放到**本次绘制区域**（外扩 5m），无需在大坐标图纸上手动找点
6. 结束后**弹窗汇总**：扫描总数、成功数、失败数，并提示保存图纸；日志窗保留显示，可继续处理下一批或关闭
7. 识别失败或绘制失败的图片会自动**复制到照片目录下的 `识别失败图片_时间戳/` 文件夹**，内含 `失败原因.txt` 清单，便于后续逐张分析；全部成功时不创建该文件夹

## 备注规则（Word 文档专用）

文档内除图片外，还可能有现场测量笔记（紧挨图片上方的文字段落），程序会自动解析并应用到紧挨下方的图片：

| 笔记样例 | 含义 | 处理逻辑 |
|---|---|---|
| `-0.1` / `-1` / `+1.3` | 该图高程偏移量（米） | 该图高程 = OCR识别高程 + 偏移量 |
| `中顶` / `左顶` / `右顶` | 位置后缀 | 高程文字标注末尾追加后缀（如 `1157.225中顶`） |
| `+0.6中顶` / `-0.2右顶` / `+1左顶` | 偏移 + 后缀 | 高程先增减偏移量，再追加后缀文字 |

备注与应用备注信息会紧邻显示在日志区，最后才打印分隔线，便于核对。

## 坐标映射规则（重要）

依据仪器屏幕的数值排列顺序（东坐标 → 北坐标 → 高程），脚本做如下映射：

| 仪器数据 | CAD 轴 | 用途 |
|---|---|---|
| 东坐标 | X | 圆心横坐标 |
| 北坐标 | Y | 圆心纵坐标 |
| 高程 | — | 以文字形式标注在圆中央；平面绘图 Z 固定为 0 |

## 环境要求与安装

- Windows + 本机已安装 **AutoCAD**（通过 COM 接口操控）
- Python 3.11，建议使用项目专用 conda 环境
- OCR 使用 **RapidOCR**（ONNX Runtime），`pip install` 即可，无需安装 Tesseract 等独立程序；首次识别会自动下载模型

```powershell
# 创建并激活专用环境（环境名与项目同名）
conda create -n AutoDrawForAutoCAD python=3.11 -y
conda activate AutoDrawForAutoCAD

# 安装依赖（opencv 指定 4.10，与 numpy 1.26 兼容）
pip install opencv-python==4.10.0.84 numpy==1.26.4 pywin32 rapidocr onnxruntime python-docx
```

> 注：python-docx 是首选解析路径；若文档为 WPS 生成的非标准 docx（缺 `docProps/core.xml`），程序会自动回退到 zipfile 直接解析 `document.xml`，无需 python-docx 也能正常提取图片和备注。

## 使用方法

### 直接运行源码

```powershell
conda activate AutoDrawForAutoCAD
python AutoDraw.py
```

弹出主窗后：
1. 选图片来源类型（图片文件夹 / Word 文档），点"浏览..."选路径，路径显示在 Entry 内
2. 点"浏览..."选目标 DWG 文件
3. 路径选齐后"开始处理"按钮自动启用；可选调整下方"绘图参数"面板的参数
4. 点击"开始处理"，日志区实时显示进度；处理完后可重新选路径继续下一批，或关闭窗口退出

### 使用打包好的 exe（推荐非开发用户）

到 [Releases 页面](https://github.com/zmq1797304904/AutoDrawForAutoCAD/releases) 下载 `AutoDraw.exe`，双击运行即可，无需安装 Python 与依赖。运行需本机已安装 AutoCAD。

## 绘图参数

参数显示在主窗"绘图参数"面板，默认值已填好，留空或解析失败时保留默认值。颜色参数用下拉框选择中文名（红/黄/绿/青/蓝/紫/白/灰）。

| 参数 | 默认值 | 类型 | 说明 |
|---|---|---|---|
| `CIRCLE_RADIUS` | 0.5 | float | 圆半径（米），图纸单位需为米 |
| `CIRCLE_COLOR` | 红 | color | AutoCAD 颜色（ACI 1=红） |
| `LAYER_CIRCLE` | 长崖边巷道 | str | 圆所在图层，不存在自动创建 |
| `TEXT_HEIGHT` | 0.8 | float | 高程文字高度 |
| `TEXT_WIDTH_FACTOR` | 0.8 | float | 高程文字宽度因子 |
| `TEXT_COLOR` | 绿 | color | AutoCAD 颜色（ACI 3=绿） |
| `TEXT_STYLE` | Standard | str | 高程文字样式（图纸中需存在该样式） |
| `LAYER_TEXT` | 长崖边巷道高程文字标注 | str | 高程文字所在图层，不存在自动创建 |
| `ZOOM_MARGIN` | 5.0 | float | 绘完后视图缩放到绘制区域时的外扩边距（米） |

修改后日志会打印 `⚙️ 参数已更新: NAME = 新值（默认 旧值）`，便于核对。

## 识别原理

- **RapidOCR**：检测 + 识别，文本框按从上到下、从左到右排序后再拼接，避免检测顺序打乱东/北/高程
- **预处理双通道**：先对原图识别；不足三个有效坐标时，再走放大 + 锐化备用通道（针对失焦/模糊照片）
- **数字筛选**：从 OCR 结果中提取所有带小数的数字，仅保留绝对值 > 100 的项（过滤点号、日期等干扰），取最后三个作为东坐标、北坐标、高程
- 使用 `np.fromfile + cv2.imdecode` 读取图片，兼容中文路径

## COM 调用容错

AutoCAD 处于忙状态（重绘、对话框、用户操作）时会拒绝 COM 调用，抛 `RPC_E_CALL_REJECTED (0x80010001)`。程序对此类瞬态错误自动重试（最多 3 次，间隔 0.5s），不影响已绘制内容。win32com 偶发的属性解析错误（"Property 'X' can not be set"）也走同样重试机制。

视图缩放（ZoomWindow）失败时仅打印警告，不抛异常——已绘制的圆和文字标注保留不受影响。

## 构建与发布

GitHub Actions 工作流（`.github/workflows/build.yml`）监听 `v*` 标签推送：
1. `build` job：在 windows-latest 上用 PyInstaller 打包 `AutoDraw.exe`（含图标 `AutoDraw.ico`）
2. `release` job：为该 Tag 自动创建 GitHub Release，并上传 `AutoDraw.exe` 作为附件

发版只需：

```bash
git tag v1.0.3
git push origin v1.0.3
```

几分钟后 [Releases](https://github.com/zmq1797304904/AutoDrawForAutoCAD/releases) 页面就会出现新版本，附件含 `AutoDraw.exe`。

> 打包后的 exe 通过 `--windowed` 模式无控制台，所有 `print` 输出改写入主窗日志区；任务栏图标通过 `SetCurrentProcessExplicitAppUserModelID` + `AutoDraw.ico` 嵌入显示。
> 注：AutoCAD 与 OCR 模型属于外部依赖，无法打包进 exe，目标机器需独立安装。

## 已知限制

- 识别准确性依赖"坐标是屏幕上最后三个大数值小数"这一版式假设，其他版式的截图可能错位
- 图纸单位需为**米**（0.5 半径才对应 0.5m）；毫米单位图纸请在 GUI 参数面板按比例放大 `CIRCLE_RADIUS`、`TEXT_HEIGHT`、`ZOOM_MARGIN`
- 对同一批照片重复运行会在相同位置叠加重复圆和文字（暂无去重保护）
- 首次运行需能访问网络以下载 RapidOCR 模型；之后使用本地缓存
- Word 文档备注解析依赖"备注在图片上方紧邻段落"的版式，跨页或备注与图片间距过大可能挂错
